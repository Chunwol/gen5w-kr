# 설치와 복구 구조

사용자 설치 방법은 [설치 가이드](beginner-guide.md), 평소 사용은 [사용 안내](vehicle-use.md)를 참고하세요.

## 배포판

기본형과 동글형 사이의 전환 기준은 [버전 사이 전환](edition-transitions.md)에 정리했습니다.

| ZIP | 설치 구성 | 시동 동의 안내 |
|---|---|---|
| `gen5w-kr-standard.zip` | wireless·audio·bridge·core·timer·bluelink (`services.odex`·`SystemUI.odex` 순정) | 순정 화면 유지, 서비스로 버튼 활성화 즉시 자동 전환 |
| `gen5w-kr-dongle.zip` | 기본형 + dongle (`/system/wifi/bcmdhd.ko` 대리 모듈, 순정 HAL 유지) | 기본형과 같음 |

점검판 `gen5w-kr-check.zip`(읽기 전용)도 릴리스에 함께 올립니다. 아래 안전판(`safe`)·무선 안전판(`safe-wireless`)은 `tools/build-all.sh`로 만들 수 있지만 릴리스에는 올리지 않습니다.

설치본과 소스는 같은 커밋에서 만듭니다. `GEN5W-VARIANT`와 `GEN5W-BACKEND`는 번들에 들어 있는 값만 씁니다. 원복할 수 없는 상태로 설치를 진행하지 않습니다.

USB의 `NEMESIS.data`는 `type=open`입니다. USB를 꽂으면 Manager만 열고, **Run USB NEMESIS.sh**를 선택하면 실행합니다.

## 맞는 버전 안내

- **동글형의 내장 Wi-Fi 확인:** 새로 설치할 때(업데이트·원복 제외) 동글 패키지의 사전 검사가 순정 `bcmdhd.ko`가 아직 있는 상태에서 내장 Wi-Fi를 찾습니다(SDIO 무선 장치, 동글 드라이버가 없을 때의 `wlan`, 커널 `Firmware up`). Wi-Fi가 꺼져 있으면 최대 8초 켰다가 다시 끕니다. 찾으면 아무것도 바꾸기 전에 설치를 멈추고, 결과 화면에 기본형을 안내합니다. 다시 끄지 못하면 설치를 멈춥니다. USB 맨 바깥의 빈 파일 `GEN5W-FORCE-DONGLE`이 있으면 확인하지 않습니다.
- **기본형에서 내장 Wi-Fi를 못 찾을 때:** 무선 기능만 빼고 설치하며, 순정 앱에 무선 코드가 있고 Wi-Fi 하드웨어가 확인되지 않았으면 `RESULT.md`·`RESULT.html`과 알림에 동글형을 안내합니다.

## 안전판 (safe, 소스 빌드 전용)

`gen5w-kr-safe.zip`은 부팅에 꼭 필요한 시스템 파일을 건드리지 않는 최소 구성입니다. 이전 코나 V039 부트루프의 원인은 확정되지 않았습니다. 이 판은 의심 경로 중 하나인 Wi-Fi·핫스팟 기능 재활성화(한국 펌웨어에서 꺼 둔 기능)를 설치 경로에서 뺐습니다.

- 설치: `gen5w.kr.bridge`(Iap2ServerApp·HKMC_DiPO·HKMC_GPM ODEX의 경로 정보 API)와 `gen5w.kr.core`(HUD 앱)만.
- 설치 안 함, 이미 있으면 순정 복원: 무선 기능 선언·핫스팟(`services.odex`, system_server)·무선 오디오(`libCarPlayAudio.so`)·시동 안내 타이머(`SystemUI.odex`).
- 무선 지원 검사를 아예 실행하지 않고 유선 전용으로 설치합니다.
- 부트가드는 2회 연속 부팅 실패에서 복구합니다(기본형은 3회).
- 설치하지 않은 모듈의 대상 파일(`services.odex`·`libCarPlayAudio.so`·`SystemUI.odex`)이 확인 도구로 순정임이 확인되지 않으면 설치를 끝내지 않고 원래대로 되돌립니다. 그래야 부트가드가 실제로 복구할 수 있습니다.
- 무선 CarPlay·Android Auto, 무선 오디오, 자동 전환 단축은 제공하지 않습니다.

## 설치 전 점검 (check)

`gen5w-kr-check.zip`은 설치 파일이 들어 있지 않은 읽기 전용 점검 USB입니다. 설치 전에 먼저 실행합니다. 릴리스에 함께 올립니다.

- 차량에 아무것도 쓰지 않습니다. 시스템 재마운트·패키지 설치·Wi-Fi 켜기·속성 변경을 하지 않습니다.
- 설치기와 같은 확인 도구로 대상 파일 6개(`services.odex`, `SystemUI.odex`, `libCarPlayAudio.so`, `Iap2ServerApp.odex`, `HKMC_DiPO.odex`, `HKMC_GPM.odex`)가 순정 V039인지 확인합니다.
- 무선 코드·Wi-Fi 장치(켜져 있을 때만)·기능 선언 파일, 기존 NEMESIS 패키지 ID, 이전 설치·부트가드 상태, 저장 공간을 기록합니다.
- 받을 버전을 추천합니다(`CHECK.txt`의 `recommend`): 동글형이 이미 설치돼 있으면 동글형, 내장 Wi-Fi가 보이면 기본형, 내장 Wi-Fi는 안 보이고 지원 동글(USB ID)이 꽂혀 있으면 동글형, 둘 다 아니면 기본형(설치기가 Wi-Fi를 잠깐 켜서 다시 확인). 점검은 Wi-Fi를 켜지 않으므로 꺼진 내장 Wi-Fi는 "확인 못 함"입니다.
- 결과: `GEN5W-REPORT/CHECK.md`(판정과 이유), `GEN5W-REPORT/CHECK.txt`(세부 값). 대상 파일을 확인하지 못했거나 부트가드가 복구할 수 없는 상태이면 "설치하지 마세요"로 판정합니다.
- 차대번호·일련번호·전화번호·핫스팟 암호·키·`/data` 파일 내용은 기록하지 않습니다.

다른 설치 ZIP에서도 `GEN5W-ACTION`에 `check`를 적으면 같은 점검을 실행합니다.

### 보고서 가드 (안전판·무선 안전판)

`gen5w-kr-safe.zip`과 `gen5w-kr-safe-wireless.zip`은 점검 보고서가 있어야만 설치합니다. 설치·업데이트를 시작하면 아무것도 바꾸기 전에 같은 점검을 다시 실행해 `GEN5W-REPORT/CHECK.txt`와 비교합니다.

- 보고서가 없으면 거부합니다.
- 보고서의 판정이 "설치 가능"이 아니거나, 지금 다시 점검한 판정이 "설치 가능"이 아니면 거부합니다.
- 점검 USB와 설치 ZIP의 빌드(`BUILD-REVISION`)가 다르면 거부합니다. 같은 빌드에서 나온 두 ZIP만 함께 씁니다.
- 펌웨어·대상 파일 6개의 순정 판정과 해시·기능 선언 파일·NEMESIS 패키지 목록·이전 설치·부트가드 상태가 한 줄이라도 다르면 거부하고 `MISMATCH` 줄로 어긋난 값을 기록합니다.
- Wi-Fi 전원·빈 공간·부팅 횟수처럼 수시로 바뀌는 값은 비교하지 않습니다.
- 설치가 실패해 되돌린 뒤에는 이전 설치 상태가 바뀌므로 점검을 다시 실행해야 합니다.

순서: `gen5w-kr-check.zip` 내용을 USB 최상위에 풀어 실행 → USB의 `GEN5W-REPORT` 폴더는 그대로 두고 설치 ZIP 내용을 같은 USB 최상위에 덮어 풀기 → 설치 실행.

## 무선 안전판 (safe-wireless, 소스 빌드 전용)

어느 판도 `SystemUI.odex`를 바꾸지 않습니다. 자동 전환 단축은 서비스(`gen5w.kr.timer`)가 맡습니다. 이 서비스는 SystemUI의 타이머 판단 로그를 따라 순정 조건이 통과했을 때만 순정 닫기 요청을 보냅니다. 안전판 두 종류는 이 서비스도 설치하지 않습니다(순정 10초).

`gen5w-kr-safe-wireless.zip`은 부팅에 꼭 필요한 시스템 파일(시동 동의 화면 `SystemUI.odex`, system_server의 `services.odex`)을 순정으로 두고 무선 CarPlay·Android Auto는 유지하는 구성입니다. system_server가 순정이면 Android가 올라오므로 부트가드·USB 복구 경로가 살아 있습니다.

- 설치: 무선 CarPlay·Android Auto 기능 선언 2개·무선 오디오·bridge·core. 무선 지원 검사는 기본형과 같이 실행하며, 지원되지 않으면 유선 전용으로 설치합니다.
- 핫스팟 모듈(`services.odex` 프로필 패치)은 설치하지 않습니다. 대신 맞춤 모드(`/data/nemesis/gen5wkr.ap-match`)를 씁니다. 무선 연결을 시작할 때 bridge가 순정 Wi-Fi 서비스로 핫스팟을 켜면서 CarPlay용 이름·암호를 넣습니다. 순정 서비스가 켤 때 이 값을 일반 핫스팟 설정으로도 저장하므로, bridge는 핫스팟이 켜진 직후(또는 깨끗하게 실패한 직후) 원래 일반 이름·암호를 순정 저장 기능(`setWifiApConfiguration`)으로 다시 저장합니다. 켜진 핫스팟은 CarPlay 값을 그대로 씁니다. 그 사이 다른 쪽이 설정을 바꿨으면 되돌리지 않습니다. 켜는 도중 전원이 꺼지면 일반 핫스팟 이름·암호가 CarPlay 값으로 남을 수 있습니다.
- 기본형·동글형도 같은 맞춤 모드를 씁니다(`services.odex`는 순정 유지). 기본형·동글형은 일반 핫스팟 메뉴를 위해 핫스팟 기능 선언(`gen5wkr.ap-hotspot-feature` 표시)을 유지합니다.
- 핫스팟 기능 선언(`com.hkmc.software.wifihotspot.xml`)도 넣지 않습니다. V039 정적 분석에서 이 기능은 상태표시줄 아이콘·핫스팟 메뉴·텔레매틱스 앱과 핫스팟이 이미 켜진 뒤의 Wi-Fi 처리에만 쓰였고, 무선 CarPlay·AA 앱과 부팅 중 핫스팟 복원은 무선 CarPlay·AA 기능만 확인했습니다.
- 이전 `services.odex` 핫스팟 패치가 설치돼 있으면 되돌리지 않고 설치를 거부합니다. 공식 업데이트로 순정 복구한 뒤 설치합니다.
- 설치 안 함, 이미 있으면 순정 복원: 시동 안내 타이머(`gen5w.kr.timer`)와 블루링크 안내 숨기기(`gen5w.kr.bluelink`).
- Wi-Fi 클라이언트(`android.hardware.wifi.xml`)는 켜지 않습니다. USB에 `GEN5W-WIFI-CLIENT`가 있으면 설치를 거부합니다. 이 파일은 벽돌이 난 V039 차량에 추가됐던 파일이고, 부팅 중 Wi-Fi를 켜는 경로를 엽니다.
- 부트가드는 2회 연속 부팅 실패에서 복구합니다. `SystemUI.odex`·`services.odex`가 순정으로 확인되지 않으면 설치하지 않습니다.
- 순정 Wi-Fi 서비스는 핫스팟 켜짐 상태(`Settings.Global wifi_ap_on`)를 저장해 두었다가, 무선 기능 선언이 있으면 다음 부팅 중에 system_server가 직접 핫스팟을 켭니다. 이 경로는 한국 펌웨어에서 실행된 적이 없어서, bridge는 핫스팟을 켠 직후 이 값을 0으로 되돌립니다. 그래서 핫스팟은 부팅이 끝난 뒤 bridge가 켤 때만 켜집니다(값을 지우기 전 1~2초 사이에 전원이 꺼지면 다음 부팅 한 번은 순정 경로를 탑니다).
- 순정 한국 펌웨어는 Wi-Fi 드라이버(`/system/wifi/bcmdhd.ko`)를 올리지 않습니다. 그래서 bridge가 처음 핫스팟을 켤 때가 그 차에서 드라이버가 처음 올라가는 때입니다. 핫스팟 시작 가드: bridge가 시작 직전에 부팅 id를 `/data/nemesis/gen5wkr.apguard/attempt`에 남기고, 깨끗한 실패 때 바로, 성공 때는 45초 유지 후 지웁니다. 다음 부팅에 이전 부팅의 기록이 남아 있으면 시작 중 재부팅으로 셉니다. 3번 연속이면 `gen5wkr.apguard.off`를 만들어 무선을 끄고 유선만 남깁니다. 성공하면 횟수는 0이 되고, 다시 설치하거나 제거하면 가드가 초기화됩니다. 점검(check)이 이 상태를 보고합니다.
- CarPlay 이름은 1~32바이트에 제어문자 없음, 암호는 8~63자 출력 가능한 ASCII만 받습니다. netd가 이 값을 `hostapd.conf`에 그대로 쓰기 때문입니다.
- 맞춤 모드에서는 핫스팟 모듈 없이 bridge가 시작됩니다. 설치 후 재부팅 전(`gen5wkr.noreboot`)에는 기다립니다.
- 미검증: 맞춤 모드의 실제 무선 연결은 실차에서 확인되지 않았습니다.

## 작업 선택

`GEN5W-ACTION`이 없으면 설치합니다. 확장자 없는 UTF-8 BOM 없는 텍스트 파일의 첫 줄로 `update`, `status`, `rollback`, `remove`를 선택할 수도 있습니다. 완료 후 파일을 지웁니다.

`install`과 `update`는 같은 교체 절차를 사용합니다. ZIP의 ID와 검사 자료를 확인하고 기존 패키지를 기기 내부에 백업합니다. 설치 전·제거 전·설치 후 훅의 결과를 직접 검사합니다. 모듈 사이에는 `/data/nemesis/gen5wkr.noreboot`로 재부팅을 억제하고 정상 완료 후 한 번 재부팅합니다.

## 이관과 자동 복구

등록된 기존 무선 패키지는 백업 후 정상 제거하고 설치합니다. 등록 파일이 없는 흔적은 임의로 삭제하지 않고 현재 원본·API 검사로 진행 여부를 판단합니다.

미지원 기능은 자동으로 건너뛰고 나머지 기능을 설치합니다. 무선을 사용할 수 없으면 무선 설정·오디오 보정을 원복하고 핫스팟 자동 보정과 Bluetooth 자동 연결을 끕니다. 유선 HUD 기반 패치·HUD 앱·주의 안내 타이머은 각각 지원 조건에 맞으면 설치합니다. 파일 손상이나 복구 실패는 중단합니다.

중단된 설치·제거는 다음 실행에서 먼저 복구합니다. 실패하면 `recovery-required`와 백업을 유지하며 재부팅하지 않습니다. `rollback`은 가장 최근 작업 직전 상태로 되돌립니다.

업데이트: 설치된 이전 빌드의 모듈은 새 빌드를 점검하기 전에 그 모듈의 제거 절차로 먼저 순정 파일을 되돌립니다. 그래서 새 빌드의 패치 내용이 바뀌어도 점검이 순정 파일을 보고 진행합니다. 새 빌드가 이 차를 지원하지 않는 모듈은 이전 빌드를 다시 설치해 그대로 두고, 그 밖의 실패는 작업 전체를 이전 상태로 되돌립니다. 동글형 업데이트·되돌리기는 동글을 꽂지 않아도 됩니다.

## 자동 분기

설치 시작 시 무선 지원 여부부터 확인합니다. 무선 기능(Wi-Fi 하드웨어)이 없으면 기존 무선 설정·오디오 보정을 원복하고 핫스팟 자동 보정·Bluetooth 자동 연결을 끕니다. Wi-Fi 확인 결과가 불확실하면 이미 검증된 기존 무선 설정은 그대로 두고, 기존 설정이 없으면 무선 기능 없이 설치합니다. 그 뒤 지원되는 유선 HUD·주의 안내 타이머을 설치합니다. 별도 파일 선택이나 CMD 실행은 필요하지 않습니다.

무선 원복에 실패하면 중단하고 백업을 보존합니다. 무선 지원 판정은 실제 휴대폰 연결 성공과는 다릅니다.

## 결과 파일

| 위치 | 내용 |
|---|---|
| `GEN5W-REPORT/STARTUP.txt` | 실행 작업과 종료 코드 |
| `GEN5W-REPORT/EXEC_LOG.txt` | 설치기 진행 기록(단계별 결과, 모듈 점검 메시지). 차량 고유 정보는 쓰지 않습니다 |
| `GEN5W-REPORT/RESULT.html` | 기능별 적용·실패·원복 결과 |
| `GEN5W-REPORT/RESULT.md` | 같은 결과의 텍스트 |
| `GEN5W-REPORT/ISSUE.md` | 검토 후 이슈에 첨부할 진단 로그 |
| 기기 `/data/nemesis/gen5w-kr-integrated/report` | 설치 작업 기록 |

진단 문서는 지정한 비식별 속성·기능·파일 해시만 읽습니다. 원시 로그·인증 자료·제조사 파일을 USB로 수집하지 않습니다. 결과 경로가 심볼릭 링크이면 저장을 거부합니다.

## 빌드

`tools/build-all.sh`가 기본형 ZIP과 대응 소스, 체크섬을 만듭니다. 검사·백업 도구는 API19 ARM 정적 실행 파일입니다. 자체 ZIP 백업 도구는 패키지 디렉터리의 심볼릭 링크와 특수 파일을 거부합니다.

세부 빌드 옵션은 `python tools/integrated/build.py --help`에서 확인합니다. 전체 검증은 [CI](ci.md)에서 수행합니다.
