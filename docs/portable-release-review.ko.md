# V039 범용판 실차 시험 후보 검토

2026-11-22. 패키지 버전 0.3.85, 사전 릴리스 `v0.3.85-rc.1`. 패키지는 커밋 `d4272df`에서 빌드했다. 실차 기능 검증이 끝난 판이 아니다.

후보 ZIP의 SHA256은 릴리스의 `RELEASE-SHA256SUMS`에 있다.
제조사 펌웨어나 라이브러리는 배포하지 않는다. 차량의 원본으로 준비한다. 동글 드라이버와 펌웨어의 라이선스는 패키지의 `dongle/licenses/`에 있다.

## 이번 수정의 근거

1. **0.3.77 홈 화면 실패.**
   - 오래된 훅이 `-Xbootclasspath/a`를 붙여 공유 dex cache를 다시 썼고, 그 결과 SIGBUS가 났다.
   - 빌드 해시 게이트, 실행 중 bootclasspath 검사, 래퍼 fail-open으로 막는다.
   - VM 시험 `BootPathVmTest`로 확인한다.
2. **0.3.79 설치 거부.**
   - 앱만 삭제돼 `/system` 변경이 남아 있었다.
   - 설치기는 이 상태에서 아무것도 바꾸지 않고, 업데이트나 삭제(순정 복구)를 먼저 하라고 안내한다.
   - 순정 복구는 설치와 별개인 복구 절차다.
3. **블루투스와 CarPlay 동시 연결.** 0.3.70~0.3.78의 `onDisableBluetooth` 억제를 없앴다.
4. **iAP2 링크 실패.**
   - 순정 서버(디컴파일로 확인)는 연결 확인 패킷을 `connected()`보다 먼저 보낸다. 이 패킷을 버리던 동작을 고쳤다.
   - 링크 실패 전체의 원인인지는 실차 로그(`path=cp5`)로 확인해야 한다.
5. **0.3.82 AP 미시작(0.3.83).** 영구 설치가 `ap.sh prepare`를 건너뛰어 AP가 시작되지 않았다. 설치 때 먼저 준비하도록 고쳤다.
6. **동글 펌웨어와 USB ID(0.3.84).** 차 커널은 `firmware_class.path`로만 펌웨어를 읽고, sysfs ID는 소문자다. 둘 다 맞췄다.
7. **동글 드라이버 구조체 배치(0.3.85).** 이전 모듈은 차 커널에 없는 WEXT를 켠 설정으로 빌드되어 `net_device` 필드 위치가 달랐다. 차 커널 배치로 다시 빌드했다.
8. **5GHz 핫스팟(0.3.85).** 순정 핫스팟은 5GHz 149번 채널을 쓴다. 이 채널을 시작할 수 있는 5개 계열만 자동 선택한다. 2.4GHz 전용 동글은 올리지 않고 이유를 알린다.
9. **동글 서비스 부하(0.3.85).** 2초마다 드라이버 별칭 769개를 다시 훑던 것을 USB 장치가 바뀔 때만 확인하게 고쳤다.

## 0.3.85 확인 결과

- 전체 회귀(`tests/run.sh`)가 rc=0으로 통과했다. 패키지 검사 6개와 과거 실패 사례 대조 39개 항목도 통과했다.
- 차 빌드 V039 VM에서 일반 설치와 동글 강제 설치가 성공했다. 각각 15분 동안 Android 리셋, SIGBUS, 앱 오류가 0건이었다.
- USB 순정 복구는 `result=restored`로 끝났고, `bcmdhd.ko`가 순정 해시로 돌아왔으며, 복구 뒤 부팅도 완료됐다.
- 설치 완료 알림과 앱 정보 탭의 "Wi-Fi 방식", "Wi-Fi 동글" 표시를 동글 방식과 사용 불가 상태에서 VM 화면으로 확인했다.
- **남은 위험:** 설치 뒤 콜드 부팅 11회 중 1회는 부팅이 끝나지 않았다. `system_server` Watchdog 뒤 Android 리셋이 났다. 그 부팅의 VM CPU는 100%였고 우리 셸 서비스 몫은 약 1.6%였지만, 원인은 확정하지 못했다. 나머지 10회는 정상 완료됐다.
- VM 커널은 3.10이라 동글 모듈을 올릴 수 없다. 모듈은 차 커널의 심볼과 구조체 배치로만 대조했다.

## 이전 판 확인 결과

- 셸 전체 회귀(`tests/run-shell.sh`)가 rc=0으로 통과했다. 같은 셸에서 bash 5.3 EXIT trap이 종료 코드를 숨기던 문제를 고친 뒤 돌렸다.
- 중계 32개, 어댑터, USB 설치기 21개, 범용판 UI, 설치 후처리, 후보 조립 시험이 통과했다.
- 동의 화면 34개, 블루링크 44개 시험이 통과했다.
- 차량 Dalvik VM: 디스패치, 앱 로컬 엔진, 캐시 미변경, bootclasspath 유지, DiPO 훅 18개 확인을 통과했다.
- 순정 V039 VM 전체 설치:
  - 설치에 성공하고 자동 재부팅했다. DiPO 훅 엔진이 앱 전용 경로로 로드됐다.
  - bootclasspath 검사 미발동, 공유 dex cache 미변경, SIGBUS 0건. 블루링크와 동의 화면 서비스가 시작했다.
  - 재부팅 뒤 부팅이 끝나지 않은 원인은 VM 한계가 아니라 우리 서비스들의 부팅 중 부하였다(블루투스 대체 서비스를 넣은 VM에서 나눠 시험). 서비스가 부팅 완료까지 기다리게 고친 뒤, 서비스를 모두 켜고 272초에 부팅이 끝났다. 실차는 미검증이다.
- 순정 `WifiSettings.odex`에 핫스팟 패치를 적용한 결과는 `fa73f5cc…`다. 시험판 레시피의 결과 해시와 같다.

## 실차에서 남는 범위

- 설치와 재부팅, 설치 후 홈 화면.
- 무선 CarPlay의 블루투스 넘김, 소리, HUD, INFO, 통화.
- 동의 화면, 블루링크, 핫스팟 스위치.
- 부트 가드와 USB 응급 복구의 실제 동작.
- 실제 동글의 드라이버 로드, 5GHz AP 시작, 순정 hostapd 호환, 휴대폰 연결.
- 설치 뒤 부팅이 반복해서 안정적인지(VM에서 11회 중 1회 멈춤).

절차는 [실차 확인 목록](portable-vehicle-checklist.ko.md)에 있다.
