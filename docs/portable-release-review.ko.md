# V039 실차 시험 후보 변경 검토

2026-11-16. 패키지 버전 0.3.65. 실차 기능 검증 완료판은 아니다.

후보 ZIP SHA256: `f19bb01acb8f636dd988d97814b435cbadfe13641d6df19b5cf597067bc5df81`.
제조사 펌웨어나 라이브러리를 배포하지 않고 차량의 원본에서 준비한다.

## 수정 범위

- 고정 전체 파일 해시 대신 인식 가능한 DEX/ODEX 구조, 검토된 오디오 ELF 영역, Dalvik ABI와 독립 실행 검사를 사용한다. 같은 V039라도 구조나 하드웨어가 다르면 모든 기능을 보장하지 않는다.
- Android 실행 중 준비한 결과를 현재 부팅과 정확한 파일 해시에 묶어 재사용한다. Android 정지 상태의 60초 복구 제한은 유지한다.
- 실제 앱의 준비 표식과 startservice 요청 접수를 구분하고, 시작 취소·업데이트·소유 프로세스 정리 경로를 보완했다.
- 독립 root USB 감시, 실패 시 자동 적용 차단, 재시도 예산과 순정 복원 검사를 유지한다.

## 이번 세 항목

1. **호스트 준비 검사:** 상위 세션에는 기존 90초 예산이 있지만 내부 검사가 10회 만에 실패하던 불일치를 수정했다. 상위 제한과 취소 조건은 유지한다. 12번째 검사에 준비되는 경우, 끝내 준비되지 않는 경우, 시작 취소를 회귀 검사했다. 실제 VM에서도 동일 APK의 PID·boot ID·starttime 준비 표식 생성과 판독을 확인했다. 이는 무선 연결 성공 판정이 아니다.
2. **캐시 검사:** 정확히 지정한 자체 생성 캐시만 릴리즈 원본의 SHA256과 일치하는 소스 확인 후 재생성으로 분류한다. OEM·알 수 없는 캐시 변경, 삭제, 읽기 실패는 계속 실패다. 실제 VM 캐시 12개는 소스 VM에서 저장한 완전한 기준과 일치했다. 권한이 부족한 경로에서 얻은 빈 기준은 폐기했다.
3. **USB 복구:** 설치된 실제 NEMESIS root 감시 서비스가 CRLF 복구 표식을 감지하고 비활성화·순정 바이트·래퍼·AP 설정 복원 검사를 수행하는 경로를 확인했다. 활성 상태의 추가 복구 결과는 아래에 기록한다.

## 검증 도구에서 확인한 오류

이번 VM에서 측정한 ADB의 `nemesis root 0`은 UID 0이어도 유효 capability가 `0xc0`뿐이어서 마운트 권한이 없다. 해당 경로의 수동 적용 실패를 제품이나 무선 모듈 문제로 판정하면 안 된다. 실제 직렬 root 콘솔과 NEMESIS root 감시 서비스는 `0x1fffffffff`였다. 검증 실행기에 CAP_SYS_ADMIN과 폐기용 /data 확인을 추가했다.

VM의 화면 조작·스케줄링 보조는 검증 환경에만 있고 차량 ZIP에는 없다. 준비·적용 확인을 실제 무선 연결이나 내비 전체 정상 판정으로 확대하지 않는다.

## 확인 결과

- Python·JVM 검사 통과. 셸 전체 회귀는 실행기에서 잘못 합쳐 호출하던 두 unittest 명령을 분리한 뒤 통과했다.
- 후보 ZIP 44파일 감사, 설치된 SHA256SUMS 및 43파일 대조 통과.
- 동일 후보가 실제 VM에서 런타임·오버레이 committed와 6개 기능 active 상태에 도달한 뒤 USB 표식을 삽입했다.
- 활성 상태 USB 복구 통과: committed/active → USB CRLF 표식 감지 → enabled=0 / disabled-restored → 런타임·오버레이 disabled, 6개 기능 stock, 세션 stopped. 순정 바이트·래퍼·AP 설정 및 마운트 해제 대조 통과.
- 적용 직전의 완전한 캐시 12개와 복구 후 12개를 대조했다. OEM 변경 0, 소스 SHA256이 일치하는 자체 bridge.dex 캐시 1개 재생성, 보호 위반 0.
- 전체 서비스 5분 유지, 실제 무선 연결, 물리 USB 마운트와 실차 기능은 통과로 기록하지 않는다. VM 시험은 이 범위에서 마감하고 정상 동기화 후 종료했다.

## 실차에서 남는 범위

실제 Bluetooth/Wi-Fi 연결·재연결, HUD·오디오·카메라·내비, 차량 전원 종료/재시작, 물리 USB의 실제 마운트와 복구를 확인한다. VM에는 이 하드웨어가 없으므로 설치·적용·소프트웨어 준비·복구 확인과 구분한다.
