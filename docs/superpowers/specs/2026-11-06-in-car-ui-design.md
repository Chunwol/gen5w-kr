# 차 안 상태·설정 화면 설계 (in-car UI)

브랜치: `feature/in-car-ui` (기준 `9df585a`, v0.3.45)

## 의도

차에서 무선이 안 되거나 설치가 의심스러울 때 "지금 어떤 상태이고 왜 그런지"를 PC 없이 헤드유닛 화면에서 보고, 기능 몇 개를 켜고 끄고, 진단을 저장할 수 있게 한다. 범용 모드 관리자가 아니다. 한국 V039 차량용, 순정 유지(stock-first), **원인을 한국어로 설명하는 화면**이 목표다.

## 목표

- INFO: 연결·설치 상태와, 대기·실패일 때 한국어 이유 한 줄.
- ONOFF: 기능만 켜고 끈다. 항목마다 "즉시 / 서비스 재시작 / 설치·제거 때만 / USB 필요 / 해당 없음" 꼬리표.
- LOG: 최근 기록을 한국어로 보여 주고 전체/오류/무선/설치로 거른다. 진단 저장 버튼.
- 관리: 전체 제거 안내(처음에는 NEMESIS Manager 제거로 연결하는 안이 기본).
- 순정 Gen5W 설정 화면과 비슷한 어두운 스타일, 왼쪽 메뉴 INFO/ONOFF/LOG/관리.

## 비목표

- 모드 설치·관리, ADB 스위치(후보, 이번 범위 밖), 차량 명령, ★ 키 재할당, 사이드 패널.
- OTA 차단(시스템 설정을 건드리므로 별도 검토).
- 부팅 경로·시스템 파일을 건드리는 변경. 이 화면은 **그런 변경을 하지 않는다.**
- HMG-API 코드·디자인 복사(AGPL). 구조만 참고한다.

## 안티 목표

- UI 때문에 부팅이나 무선이 나빠지는 것. UI가 죽어도 무선·HUD는 지금처럼 돌아야 한다.
- 추정을 사실처럼 표시하는 것. 읽지 못한 값은 "확인 못 함"으로 표시한다.
- 전체 제거를 한 번 누르고 바로 실행하는 것.

## 제약

- 대상: Kona HEV, 한국 V039(`260902`), 기본형 + 내장 Wi-Fi(`standard` / `builtin`).
- Android 4.4.2, minSdk 18, mksh. 기존 코어 앱(`kr.gen5w.core`)은 서비스만 있고 화면이 없다.
- 일반 앱은 `/data/nemesis`에 쓸 수 없다. 설정 파일 쓰기는 특권 헬퍼(`StockOwner`처럼 NEMESIS가 띄우고 소켓에서 호출자 uid를 확인하는 방식)가 한다.
- 전체 테스트(`tests/run.sh`)와 unit-commands 정책을 통과해야 한다.

## 결정한 것

- **언어**: 로그 파일과 진단 파일의 원문은 **영어 코드 그대로 둔다**(`FAIL bridge:`, `WAIT bridge:`). 테스트·설치기의 `report()`·진단 도구가 이 접두어에 의존하고, 진단을 사람·도구가 같은 형식으로 읽어야 하기 때문이다. **화면에서만 한국어로 번역**한다. 번역 표에 없는 줄은 원문 그대로 보여 준다.
- **제어 방식**: 즉시 적용 항목은 기존 마커 파일(`gen5wkr.wireless-disabled`, `gen5wkr.apguard.off`)을 특권 헬퍼가 만들고 지우는 방식. 감시 프로그램이 2~5초마다 확인하므로 감시 쪽 코드는 바꾸지 않는다.
- **읽기 전용부터**: 1단계 INFO·LOG(읽기 전용), 2단계 무선·apguard 스위치, 3단계 나머지 스위치, 4단계 관리(제거 안내).
- **동글 항목**: 백엔드가 `dongle`일 때만 활성. 이 차(`builtin`)는 "해당 없음".

## 빌더에게 남긴 것 (내 판단, 확인 필요)

- 화면 진입 방법(런처 타일 / NEMESIS Manager의 Launch / 설정 버튼 두 번)은 **차에서 확인하기 전에는 모른다.** 구현은 앱 안에 Activity를 만들고 NEMESIS Launch로 열 수 있게 하는 것까지만 한다.
- 즉시·서비스 재시작 꼬리표는 코드를 읽고 정한 것이다. HUD·블루링크·시동 안내창의 런타임 토글은 구현 후 PC 테스트와 차 확인이 필요하다.
- 화면 크기와 폰트는 1024x600 가정. 실제 해상도는 모른다.
- 순정 설정 화면 사진이 오면 색과 간격을 맞춘다.
