# 고속도로 안내·순정 카메라 경고 추가 구현 로드맵

작성: 2026-10-28 · 기준 코드: `48d785d` / v0.1.5 · 상태: 사용자 개발 승인 · 오프라인 추가 조사 및 1차 수정 완료

이 문서는 개발 범위와 진행 조건을 정합니다. 최초 보고 이후 사용자가 조사 완료 후 가능한 개발을 승인했습니다. 이후 조사에서 발견한 AA 버전 식별 문제를 수정했습니다. 정적 코드 대조는 실차 동작 확인과 구분합니다. 릴리스·USB는 v0.1.5를 유지합니다.

## 결론

1. 순정 카메라 경고에는 데이터 전달 지점과 실제 송신 코드가 있습니다. **순정 데이터 생성을 유지하고, 프로젝션이 그 경고를 덮는 부분을 줄이는 방향**을 우선합니다.
2. 다만 프로젝션 중에도 데이터가 계속 생성되는지는 아직 확인되지 않았습니다. 입력 확인 없이 API 호출부터 추가하지 않습니다.
3. V039의 `updateTPHighwayMode`는 빈 송신 함수로 끝납니다. 호출 복원만으로 전용 표시가 구현되지 않습니다.
4. 별도 `HuCluPE03`, `HuCluPE12`, `RoadEventInfo`의 실제 송신 코드도 발견했습니다. 이들이 고속도로 표시용인지, 코나 HUD가 해석하는지는 미확인입니다. 이름만 보고 대체 경로로 쓰지 않습니다.
5. 기존 회전 표시에서 IC·JC·TG 등을 정확히 표시하는 개선과, 순정 고속도로 전용 화면 구현은 별도 완료 항목으로 관리합니다.
6. `SOUND_ON` 자동 전송은 복원하지 않습니다. 자체 CAN 프레임, MICOM 펌웨어 수정, 지도 DB 재배포도 범위에 넣지 않습니다.

## 대상 휴대폰과 연결 방식

사용자 요구: **아이폰 CarPlay와 안드로이드 Android Auto를 모두 지원 대상으로 조사·개발**합니다. 한쪽 성공을 다른 쪽 성공으로 처리하지 않습니다.

| 구분 | 조사할 입력·수명 경로 | 별도 확인 |
|---|---|---|
| 아이폰 유선 CarPlay | DiPO·iAP2 길안내 수신·등록·USB 해제 | 순정 내비 상태 변경, 경고 초기화와 통화 |
| 아이폰 무선 CarPlay | DiPO·무선 세션·길안내 수신·연결 종료 | Wi-Fi 끊김·재연결·유선 전환에서 잔류 표시 |
| 안드로이드 유선 Android Auto | 순정 GPM 기본 길안내 경로와 앱 보조 AA 경로를 구분 | GPM의 경고 초기화, 실제 USB 해제·세션 종료 |
| 안드로이드 무선 Android Auto | 실제 무선 AA 세션 성립·GPM 이벤트·연결 종료부터 확인 | 무선 CarPlay 성공을 무선 AA 성공의 근거로 쓰지 않음 |

현재 지원 확인과 앞으로의 지원 목표를 구분합니다. 코나 V039에서 특정 연결 방식이 성립하지 않으면 그 제한과 원인을 별도 보고하며, 공통 코드가 있다는 이유로 네 구분을 모두 지원 완료로 표시하지 않습니다.

네이버지도·카카오맵·티맵은 양쪽 OS에서 실제 수신되는 정보가 다를 수 있습니다. 지원되는 앱/OS 조합별로 회전·거리·차선·고속도로 정보와 순정 카메라 경고 공존을 기록합니다. 휴대폰 앱의 카메라 정보와 순정 지도 DB의 카메라 정보를 섞지 않습니다.

## 2. 선택할 구현 방식

| 방법 | 장점 | 한계·위험 | 판단 |
|---|---|---|---|
| 순정 내비가 경고를 계속 보내도록 두고 프로젝션의 불필요한 덮어쓰기를 제한 | 기존 지도 DB·경고 판단·송신 API를 이용하며 새 카메라 계산이 필요 없음 | 순정 엔진이 프로젝션 중 데이터를 계속 만드는지 확인해야 함. 모든 초기화를 무조건 막으면 잔류 경고가 생길 수 있음 | 우선 추진 |
| 순정 데이터의 별도 읽기 경로를 확보해 필요한 경고만 중계 | 출처·유효시간·소유권을 명확히 관리할 수 있음 | 외부 구독 API가 확인되지 않음. 새 IPC 또는 ODEX 변경이 필요할 수 있음 | 첫 방식으로 해결되지 않을 때 별도 설계 |
| 외부 카메라 DB·위치로 자체 경고 생성, 빈 송신 함수 직접 구현 | 기능을 임의 확장할 여지 | 데이터 권리·위치 정확성·새 프로토콜·안전 책임이 커지고 기존 프로젝트 범위를 벗어남 | 이번 범위에서 제외 |

고속도로는 먼저 기존 회전 경로의 정확도를 높입니다. 전용 화면은 E3의 별도 OEM 경로가 해당 정보에 사용된다는 근거와 코나 지원이 모두 확보됐을 때만 별도 기능으로 진행합니다.

## 3. 단계별 진행

### 1단계 — 입력·출력 경로 확정 (첫 개발 단계)

작업:

- 보관된 지도/BIN·업데이트 이미지에서 네이티브 두 라이브러리를 읽기 전용으로 찾아 파일 해시와 빌드 일치를 확인합니다. 없으면 자료 부재를 기록합니다.
- NativeCall.sendClusterData를 호출하는 네이티브 경로, 프로젝션/음소거/안전운전 상태의 영향을 추적합니다. JNI 연결을 메서드 이름만으로 확정하지 않습니다.
- Android Auto는 GPM 초기화 호출 다섯 곳의 이벤트·인자·실행 조건을 표로 정리합니다. CarPlay는 DiPO의 Route_Guide_ACTION/SOUND_OFF와 순정 내비 수신 분기를 따로 추적합니다. GPM 보완을 CarPlay에도 적용된다고 간주하지 않습니다.
- 두 OS에서 길안내 입력이 실제 어디로 들어오는지와 세션 종료 신호를 유선·무선별로 확인합니다. Android Auto의 순정 GPM 경로와 보조 AA 브리지를 혼동하지 않습니다.
- 필요할 때만 읽기 전용 관측을 설계합니다. 메시지 종류별 횟수·시각·유효 여부만 기록하고, 위치·도로명·전체 배열·차량 식별자는 수집하지 않습니다. 기존 리스너로 가능한 것과 새 계측이 필요한 것을 구분합니다.
- 출력은 하지 않습니다. 계측용 변경이 필요하면 순정 파일 해시·복원 계획과 함께 별도 설명합니다.

완료 조건:

- 프로젝션 전/중/종료, 순정 경로 없음/안내 중, 음소거/통화 상태별로 경고 입력이 생성되는지 확인합니다.
- 정적 분석으로 분기만 확인했다면 생성 성공으로 표시하지 않습니다. 실차 또는 동등한 엔진 실행 증거가 필요합니다.
- 데이터가 안 나오면 2단계 출력을 시작하지 않습니다. 엔진 유지가 음소거·통화·순정 안내에 간섭하지 않는 방법인지 먼저 설계합니다.

### 2단계 — 순정 카메라 경고 보존

작업:

- 1단계에서 순정 경고가 계속 생성되는 경우, GPM이 유효한 순정 경고를 덮는 조건만 제한합니다. 모든 초기화를 일괄 제거하지 않습니다.
- 순정 내비의 판단과 writer를 우선합니다. 앱이 카메라 종류·제한속도·거리·통과를 추측하지 않습니다.
- `SOUND_ON`, 순정 목적지 설정, 음소거 설정은 건드리지 않습니다. 순정 경로 ACTIVE/UNKNOWN에서는 앱의 회전 출력·지우기 보류 정책을 유지합니다.
- 동시성·출처·종료 처리를 먼저 검증한 뒤에만 새로운 경고 중계 방식을 고려합니다. UID만으로 서로 다른 system 앱을 구별할 수 있다고 가정하지 않습니다.

완료 조건:

- CarPlay와 Android Auto 각각에서 실제 새 경고 입력으로 표시되고, 통과·안내 종료·엔진 종료 시 잔류하지 않습니다. 각 연결 방식별 결과를 따로 남깁니다.
- CarPlay/AA 전환과 순정 내비 안내 시작/종료 때 경고와 회전이 서로 지워지지 않습니다.
- 통화·사용자 음소거를 변경하지 않습니다.

중계가 필요한 경우의 추가 조건:

- `NativeWarningState` 같은 순수 상태 모델로 출처·입력 세대·수신 시각·유효/해제/미확인을 구분합니다. 소스가 바뀌면 이전 캐시를 폐기합니다.
- 경고와 거리를 임의로 짝짓지 않습니다. 엔진 메시지들의 실제 연관·갱신 주기를 확인합니다.
- 유효시간은 관측한 갱신 주기와 종료 신호를 근거로 결정합니다. 임의의 30초 유지나 주기적 과거 경고 재전송은 금지합니다. 값이 확정되기 전 중계 배포는 하지 않습니다.
- 신뢰할 데이터가 끊기면 앱이 마지막 경고를 계속 재생하지 않습니다. 앱이 소유한 출력만 해제하며 다른 순정 writer의 경고를 지우지 않습니다.

### 3단계 — 고속도로 정보 개선과 전용 출력 판정

일반 안내 개선:

- CarPlay의 현재 Maneuver와 Android Auto 순정 GPM/보조 브리지의 입력 차이를 먼저 확인한 뒤, 구조화된 종류·방향·거리·선택된 회전을 공통 의미 모델에 맞춥니다. CarPlay 전용 파서만 고쳐 양쪽 구현 완료로 처리하지 않습니다.
- 도로명에 IC/JC/TG 문자열이 있다는 이유만으로 확정하지 않습니다. 단어 경계·한국어 명칭·회전 종류를 교차 확인하고, 불명확하면 일반 회전 표시를 유지합니다.
- 이름만 보고 휴게소 목록을 만들거나, 거리·교통상태를 기본값으로 정상이라고 꾸미지 않습니다. 현재 쓰이지 않는 HighwayFrame의 traffic=0 같은 값도 의미 확인 없이 활성화하지 않습니다.
- 지도 앱이 보내지 않은 다음 휴게소·IC 목록을 순정 목적지와 섞어 만들지 않습니다.

전용 출력 조사:

- HuCluPE03/PE12/RoadEventInfo의 순정 입력 출처·payload 의미·전송 조건을 조사합니다. 이들이 고속도로 표시 API라는 가정은 하지 않습니다.
- 순정 고속도로 안내가 어떤 경로를 쓰는지와 코나 계기판·컴바이너 HUD 중 어디에 표시하는지 구분합니다.
- 동일 V039·코나에서 확인된 OEM API와 정확한 입력 의미가 있어야 전용 backend를 구현합니다. 임의 바이트를 해당 API에 넣어보는 방식은 사용하지 않습니다.

완료 조건:

- 실제로 지원되는 정보만 종류·명칭·거리·방향으로 정확히 표시하고, 재탐색·지도 변경·경로 종료 때 초기화합니다.
- 단순 회전 아이콘을 전용 고속도로 목록 구현 완료로 표시하지 않습니다.
- 대체 OEM 경로 또는 하드웨어 수용이 확인되지 않으면 전용 화면은 미지원으로 유지합니다. 빈 함수 호출을 되살리는 것으로 완료 처리하지 않습니다.

### 4단계 — 통합 검사와 배포

- 순수 상태/변환 테스트에는 합성 입력만 사용합니다. 실제 위치·카메라 경고를 주입하는 차량 시험 도구는 만들지 않습니다.
- 기존 Core lifecycle·HUD·소유권·설치 원복 검사를 재사용합니다. 필요한 경계 검사만 추가하고, 전체 검사는 CI에서 한 번 실행합니다.
- 순정 파일이 바뀌는 경우에만 원본/패치 해시·APK 조합·이전 패치 업그레이드·전원 중단·제거 원복을 확인합니다. 검증되지 않은 펌웨어는 기능 제외합니다.
- 최종 통합본 준비 후 실차 확인을 한 묶음으로 진행합니다. 기존 v0.1.5 ZIP·USB 백업을 복구 경로로 유지합니다.
- 실차 미확인 상태의 배포라면 기능별로 그 상태를 표시합니다. 지원 차종 전체에 성공을 확대하지 않습니다.

## 승인할 개발 범위

추천 범위는 **1단계에서 경고 입력·초기화 충돌을 확정한 다음 2단계 구현, 고속도로는 기존 안내 개선과 전용 경로 조사를 분리해 3단계로 진행**하는 것입니다. 입력·하드웨어가 확인되지 않은 기능의 완료 시점은 확정하지 않습니다.

## 추가 조사·1차 개발 결과

사용자 승인 후 V035/V039 원본을 해시로 다시 대조했습니다. 기존 gpm-v039 프로필의 원본 8c5104…와 APK 756aa2…는 실제 V035 파일이었습니다. V039의 원본은 caee2c…와 APK 8e7e98…입니다. 조사 경로의 V039 명칭만으로 버전을 정하지 않습니다.

수정한 내용:

- gpm-v035.json을 분리하고, 실제 V039에서 gpm-v039.json을 새로 생성했습니다.
- 버전별 getter 이름(bJ/bG)과 그 뒤 NavigationManager 할당 분기를 함께 확인한 뒤 정확한 조건 분기만 패치합니다.
- 두 ARM helper를 각각 빌드하고 APK/ODEX 버전 조합 검증과 백업·원복을 적용합니다.
- 합성 설치 검사에서 두 버전 및 잘못 섞인 조합 거부를 확인했습니다. 실제 원본에도 ARM 도구로 적용해 출력 SHA256과 반대 버전 거부를 확인했습니다.

추가로 V035/V039의 automotive-service 원본 DEX에서 sendTPHighWay가 return-void 한 명령뿐임을 각각 확인했습니다. 네이티브 libExSLAndroidJNI/libExSLNavi는 현재 검색한 추출 디렉터리와 두 시스템 이미지의 lib 경로에 없었습니다. 지도/BIN 저장 영역의 네이티브 엔진 입력을 확보하기 전에는 카메라 생성 지속 여부를 확정할 수 없습니다.

**아직 구현하지 않은 부분:** GPM 경고 초기화 억제, 카메라 중계, 고속도로 전용 출력. 입력·종료 조건과 하드웨어 수용이 확인되지 않아 임의 패치를 추가하지 않았습니다. 다음 근거는 정확한 지도/BIN 엔진 파일 또는 순정 입력의 실행 관측이며, 단순 API 존재·합성 테스트로 대체하지 않습니다.
