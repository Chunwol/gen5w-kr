# Vehicle candidate 0.3.67 implementation plan

> Execute inline with test-driven changes; request one independent review before USB delivery.

**Goal:** Produce the next installable vehicle candidate with reproducible transport lifecycle fixes and useful opt-in audio/HUD/split-screen diagnostics.

**Architecture:** Preserve the existing guarded overlay/runtime and stock audio/resource handling. Give HUD input generations a transport identity so handover cannot reuse the previous route subscription or let its late disconnect clear the new link. Add fixed-field trace records and bounded active-session snapshots to the existing diagnostic export.

**Tech stack:** API18/19 Java and Dalvik, mksh, Python packaging, ARM helpers.

**Spec:** User requests the next vehicle-executable version, maximum justified code fixes, and detailed debugging enabled for that trial. Failures are vehicle audio, HUD, and the OEM INFO split pane beside CarPlay.

## Constraints

- Preserve existing uncommitted 0.3.66 work, USB logs, recovery guards and stock navigation priority.
- Do not force DiPO activated state, microphone/audio ownership, or HUD permission based on guessed success.
- Debug output must be bounded and switchable; do not log packet payloads or destinations in authored traces.
- Validate changed behavior with regression tests and build/audit the exact shipped artifacts.
- Final release notes must distinguish PC validation from unverified vehicle functionality.

## Tasks

1. Reproduce a 4-to-5 handover retaining a route subscription epoch and a late old-transport disconnect invalidating the new session. Implement transport-aware epochs and use them at CoreService callback boundaries; retain duplicate-event behavior.
2. Add switchable fixed-field projection/HUD trace and bounded active snapshots for manual diagnostic saves, including successful-but-broken sessions. Preserve automatic first-failure evidence. Default the trial's debug mode on, allow disabling it, and export the resulting logs through Manage > Save diagnosis.
3. Build fresh app/adapter payloads, version the candidate as 0.3.67, run relevant Java/shell/adapter/packaging checks, obtain an independent review, and stage the verified installer on F: after backing up the four previous installer files.

## Review focus

- A delayed disconnect from transport 4 must not close transport 5.
- A real current disconnect must invalidate queued input and stop retries.
- Normal USB and duplicate callbacks retain their existing semantics.
- Debug mode off produces no trace worker; debug mode on has fixed storage/time bounds.
- Manual snapshots must not overwrite first-failure evidence or block the UI collector indefinitely.
