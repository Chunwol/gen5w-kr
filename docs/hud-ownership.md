# 순정 내비와 HUD 우선순위

순정 내비의 목적지 안내가 활성 상태이면 순정 안내를 우선합니다. CarPlay 회전·차선·거리 출력과 지우기·재전송을 모두 보류하고, 순정 안내가 끝나면 최신 CarPlay 정보를 다시 보냅니다. CarPlay 안내가 그동안 끝났다면 이전 회전 정보를 다시 표시하지 않습니다. 화면에서 순정 지도를 닫았다는 사실만으로 목적지 안내가 종료됐다고 간주하지 않습니다. 순정 `State_Destination` 값이 0으로 확인될 때에만 CarPlay 출력이 허용됩니다.

보조 Android Auto 안내는 순정 안내가 활성화되거나 순정 상태를 확인하지 못하면 이전에 저장한 회전 정보를 비웁니다. 이후 보조 송신기가 새 안내를 보낼 때 다시 표시합니다. 순정 GPM의 기본 경로는 이 보조 상태와 별개입니다.

순정 안내가 활성화되거나 상태를 확인할 수 없게 되면 보조 AA 캐시는 버리지만, 화면을 지우는 요청은 예약하지 않습니다. 따라서 그 프레임이 순정 또는 새 안내에 덮이기 전까지 남을 수 있습니다. 순정 안내 없음 상태로 돌아왔을 때 무조건 지우면 그 사이 순정 GPM이 출력한 안내를 지울 수 있으므로, GPM 실제 출력 소유권을 확인할 신호가 마련되기 전에는 자동 지우기를 적용하지 않습니다.

## 안내 상태 확인

순정 서비스가 사용하는 `content://com.mnsoft.navi/State_Table`의 `State_Destination` 열만 읽습니다. 1은 안내 중, 0은 안내 없음입니다. 위치·목적지·주소·연락처는 조회하지 않습니다. 테이블 없음·빈 응답·다른 값·권한 오류는 확인 불가로 처리하고 CarPlay HUD 출력을 보류합니다.

해당 제공자는 일반 앱에 공개되어 있지 않아 NEMESIS가 `owner` 서비스를 system UID 1000으로 실행합니다. 이 서비스는 우리 APK의 UID에서 온 요청만 받고, 앱도 상대 UID가 1000인지 확인합니다. 로컬 소켓으로 안내 중·없음·확인 불가만 전달하며 외부 통신은 하지 않습니다.

출력 직전마다 상태를 다시 조회합니다. 조회 서비스가 멈추거나 응답하지 않아도 CarPlay가 순정 출력을 덮어쓰지 않도록 보류합니다. 1초 재시도로 서비스 복구와 순정 안내 종료를 확인합니다. 순정 프로세스의 상태 갱신과 화면 출력이 하나의 원자적 작업은 아니므로, 실제 전환 시점은 차량에서 확인해야 합니다.

## 과속·카메라 경고

분석 자료에서 순정 경고·제한속도 API는 회전·차선·거리와 분리된 별도 채널로 확인됐습니다. 실제 호출 주체와 시점, 화면 출력은 확인되지 않았습니다. 우리 앱은 이 API를 호출하지 않으며, 순정 경고를 생성·해제하거나 음소거 상태를 바꾸지 않습니다:
- 회전·거리: `NavigationCluster.updateTBTInfo(IIFFIIIII)` 및 차선 프레임 (우리 앱이 CarPlay/Android Auto에서 수신하여 전송)
- 과속·카메라: `NavigationCluster.updateTBTTrapInfo(17개 int)` 및 경고 거리 `updateNaviWarnDist(3개 int)` (안전운전 모드에서 누가 언제 전송하는지는 확인되지 않음)

### 순정 경고와 음소거

순정 프로젝션이 실제 경고 표시와 내비 소리에 미치는 영향은 확인 중입니다. 앱은 `SOUND_ON` 신호를 보내지 않으며, 서비스 시작·프로젝션 종료·HUD 소유권 변경·안내 갱신 때도 사용자나 순정 서비스가 정한 음소거를 해제하지 않습니다.

순정 목적지 안내가 활성인 동안에는 CarPlay 회전 HUD 출력을 양보합니다. 이 보호 판정은 지도 화면이 보이는지 여부가 아니라 `State_Destination` 안내 상태를 따릅니다. 순정 과속·카메라 경고 채널은 건드리지 않지만, 순정 경고와 CarPlay 회전 HUD가 차량 화면에서 동시에 표시되는지는 실차 확인 전까지 보장하지 않습니다. 별도의 카메라 경고를 생성하거나 순정 음소거를 강제로 풀지 않습니다.

앱 시작 시 경고·거리·제한속도 출력 메서드의 이름·인자·반환형만 조사하고 `hud-native-warning.status`에 다음 중 하나를 기록합니다. 조사 중 출력 메서드를 호출하거나 위치·속도·카메라 값을 저장하지 않습니다. 이 상태는 순정 내비 활성 상태나 HUD 표시 성공과 별개입니다.

| 상태 | 의미 |
| --- | --- |
| `APIS_PRESENT_SOURCE_UNOBSERVED` | 세 종류의 순정 경고 API 확인, CarPlay 중 경고 입력·표시 미확인 |
| `APIS_INCOMPLETE_SOURCE_UNOBSERVED` | 일부 API만 확인, 경고 입력·표시 미확인 |
| `APIS_UNAVAILABLE_SOURCE_UNOBSERVED` | 확인한 API 없음 또는 조회 실패, 경고 입력·표시 미확인 |

## 결과 확인

USB `GEN5W-REPORT/RESULT.html`의 **HUD 최근 출력 상태**에서 CarPlay 허용·순정 우선·확인 불가를 확인합니다. 설치 직후나 서비스 실행 전에는 아직 확인되지 않음으로 표시될 수 있습니다. 이 항목은 마지막으로 기록한 상태이며 차량의 현재 화면을 보증하지 않습니다.

## 보조 Android Auto 종료 처리

순정 GPM의 `com.telechips.android.gpm.finish`를 받으면 활성 AA 안내 상태가 있을 때 이를 비우도록 처리합니다. 이때 순정 내비가 안내 중이거나 상태를 확인하지 못하면 화면 지우기를 보류하고, 순정 안내가 끝난 뒤 처리합니다. CarPlay 안내가 활성화되어 있으면 그 안내를 다시 표시합니다. 안내 갱신이 30초 동안 없다는 이유로 지우지는 않습니다. USB 장치 모드 상태 알림은 휴대폰 분리의 근거로 사용하지 않습니다. 보조 송신기의 종료 알림이나 GPM 종료 신호를 받지 못하는 경우에는 안내가 남을 수 있습니다.

해시로 원본을 확인한 V039 Navi ExSL ODEX의 `NaviETCReceiver.onReceive` 원시 바이트코드에는 `com.telechips.android.gpm.set`과 `.finish` 두 신호를 비교해 Android Auto 연결·해제 로그와 내부 이벤트를 남기는 코드가 있습니다. 이 코드만으로 모든 연결 방식에서 신호가 전달되는지, 신호를 보내는 주체와 이벤트 의미, 화면 출력 소유권까지 확인되지는 않습니다. 따라서 연결 신호 수신만으로 기존 안내를 지우지는 않습니다.

`SOUND_OFF`를 받아 `SOUND_ON`을 재전송하던 동작은 제거했습니다. 통화 상태나 음소거 원인을 추측해 설정을 바꾸지 않습니다.
