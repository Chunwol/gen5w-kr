# 검증 범위

## 자동 검증

CI는 다음 항목을 한 번에 확인합니다.

- 패키지·APK·DEX·ARM 도구 빌드와 설치 ZIP 구성
- HUD 메시지 파싱, 회전·거리·차선 변환, 안내 종료·연결 해제 처리
- Bluetooth 상태 전환, 재시도, 유선 연결 우선 처리
- 원본 불일치 거부, 설치·업데이트·제거·원복, 중단 후 재실행
- 등록된 이전 개인용 구성에서 기본형으로 전환, 시동 안내 원본 복원
- 기능별 결과와 진단 문서 생성
- 오디오 수정 코드의 ARM 실행과 형식·변환 경로
- 제조사 파일·컴파일용 선언·개인 키의 설치물 포함 여부
- 두 설치 ZIP과 대응 소스, 체크섬, 코드 커밋 일치
- 헤드유닛 명령 호환: 차에서 실행되는 셸 스크립트가 헤드유닛에 있는 명령과 toolbox 옵션만 쓰는지 정적으로 검사합니다(`tests/unit_commands.py`). 빌드된 설치 ZIP 안의 스크립트도 빌드 직후 같은 방식으로 검사합니다(`--dist`). 모의 시험 중에도 차에 없는 명령(`printf`, `head`, `sed` 등)이나 옵션(`mv -f`, `cmp -s`)을 쓰면 차에서처럼 실패하고 기록됩니다(`tests/unit/shim.sh`). 허용 목록은 `tests/unit/commands.txt`(명령 이름만)와 `tests/unit/policy.txt`입니다.

헤드유닛의 실제 mksh·toolbox로 확인하는 검사는 제조사 파일이 필요해 로컬에서만 실행합니다: `tools/unit-real-check.sh <system.img>`(qemu-user 필요, root 불필요). 스크립트 문법, 명령 목록, toolbox 옵션, 셸 내장 기능을 확인합니다. qemu에서는 헤드유닛 셸이 하위 프로세스를 만들 때 멈추므로, 스크립트 전체 실행은 모의 시험이 맡습니다.

순정 파일 대조는 저장소 밖의 로컬 자료로 수행합니다. CI에는 합성 입력과 자체 코드만 사용합니다.

## 차량에서 확인할 항목

코드와 모의 환경의 검증 결과가 실제 차량 동작을 대신하지는 않습니다. 다음 항목은 차량별 확인이 필요합니다.

| 항목 | 확인할 내용 |
|---|---|
| 무선 연결 | 인증, 시동 후 재연결, 실패 후 유선 전환 |
| 소리 | 음악, 지도 안내, Siri 음성 |
| HUD | 아이콘·거리·차선 순서, 순정 앱과의 공존 |
| 지도 앱 | 앱별 안내 정보, 재탐색·안내 종료 시 표시 지움 |
| 시동 안내 | 일반 부팅과 QuickBoot |

확인되지 않은 방향이나 입력을 임의의 아이콘으로 표시하지 않습니다. 좌측 통행 회전교차로는 일반 원형 아이콘을 사용하며, 차선 index와 물리적 좌우 순서의 대응은 확인이 남아 있습니다.

## 버전 확인

릴리스의 `RELEASE-SHA256SUMS`로 설치 ZIP을 확인합니다. ZIP 안의 `BUILD-REVISION`은 빌드한 소스 커밋이며, 같은 릴리스의 `gen5w-kr-source.zip`이 대응 소스입니다. [CI 결과](https://github.com/Chunwol/gen5w-kr/actions)와 [릴리스](https://github.com/Chunwol/gen5w-kr/releases)에서 확인할 수 있습니다.
