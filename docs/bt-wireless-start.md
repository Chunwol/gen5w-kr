# Bluetooth 자동 무선 시작

자체 서비스가 실제 광고된 iAP UUID(CAFF 우선, CAFE 대체)를 확인하고 연결합니다. 이름에 iPhone이 있다는 이유로 선택하지 않습니다. 단일 세대의 RFCOMM 입출력, 인증·정보 요청 대기, 중복 억제, 지연 콜백 폐기, 실패 후 재시도와 유선 우선 처리를 구현했습니다. 핫스팟 키는 메모리에서만 사용하며 메시지·주소·키를 로그에 넣지 않습니다.

여러 휴대폰이 연결돼도 선택된 후보는 실제 연결 해제까지 유지합니다. 주기적인 다른 휴대폰 발견으로 실패 횟수나 재시도 대기 시간을 초기화하지 않습니다. 선택된 휴대폰의 연결이 해제되면 새 후보를 받을 수 있습니다.

유선 우선은 CarPlay USB 알림뿐 아니라 Apple USB host 장치와 순정 `sys.usb.config`/`sys.usb.state`의 정확한 `carplay_connect` 토큰을 시작 시·주기적으로·native 시작 직전에 확인합니다. Apple USB가 연결되면 충전만 하는 연결이라도 무선 자동 시작을 보수적으로 대기합니다. 원래 USB 세션을 끊을 수 있는 강제 native 종료는 하지 않습니다. 이는 초기 유선 감지와 자체 브리지 억제의 보강이며 순정 USB 전환 전체의 실차 성공을 뜻하지 않습니다.

순정 `Iap2SvcMain()`은 true만 반환하고 실제 세션을 열지 않습니다. 공개 API만으로 순정 투영 서비스를 시작할 수 없어, 정확한 V035/V039 APK/ODEX 해시에 제한된 작은 자체 제어부를 사용합니다. iAP2 onStartCommand는 stock 연결 관리자에 외부 Bluetooth 연결/해제를 요청하고, DiPO의 기존 무선 시험 동작은 stock 생성·시작 메서드에 연결합니다. 원래 USB 경로와 나머지 분기는 보존합니다. [설치·복구](bridge-install.md), [DiPO 제어부](dipo-control.md).

한국 사양의 iAP2 초기화가 지역 조건으로 끄던 Wi-Fi 정보·길안내 지원도 기존 프로토콜 구현을 사용하도록 활성화합니다. 실제 인증은 순정 네이티브와 차량 인증 장치가 수행하며 인증서·키를 복사하지 않습니다. 순정 서비스의 ReadDone=false는 입력 실패를 뜻하지 않지만 WiFiRequestInformation의 false는 준비 미완료/실패이므로 제한 시간 안에서 재시도합니다.

PC에서 상태·취소·재시도·native helper·원본 복구를 검증했습니다. TCP7000 수신 대기는 투영 서버 준비 확인일 뿐 휴대폰 연결 성공의 증거가 아닙니다. 실제 무선 연결과 시동 후 재연결은 최종 실차 확인 대상입니다.
